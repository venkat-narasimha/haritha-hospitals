Leave Management

Leave Management configures leave types + policies + periods, allocates days per employee, and records every leave movement as an immutable Leave Ledger Entry.

  • 7 Leave Types (CL, SL, EL, …).
  • 3-layer model: Config → Policy → Action.
  • Audit trail via Leave Ledger Entry.
Config (Leave Types)CL · SL · EL · …
Policy (Allocation + Approvers)per Grade / Type
Action (Application + Ledger)immutable ledger
Leave is three layers deep: Config defines types, Policy allocates days, Action records actual movement on an immutable ledger. The deep-dive deck shows each layer + the workflows.

How the modules connect

A real Day 1 scenario showing the modules in concert for one new hire — Employee A.

Org Mgmt
Step 1. Employee A is hired → Employee record created with Department (Nursing) + Branch (Main).
Shift Mgmt
Step 2. Auto-assigned to Morning shift (06:00–14:00) for 30 days.
Attendance
Step 3. Biometric punches → Auto Attendance creates Attendance row (Present).
Leave Mgmt
Step 4. Employee A applies Sick Leave for Day 5 → Approver approves → Ledger posts.
Lifecycle
Step 5. After 90 days, Probation review → confirmed via Employee Promotion.
Walk through the five steps in order. This is the same employee across all five modules — every module plays a role in their first 90 days. Note that the order is intentional: define the person first, schedule them, then track presence, then absence, then growth.
