## 1. End-to-end shift lifecycle

From Employee onboarding to monthly payroll. One big picture.

```mermaid
    subgraph Setup["ONE-TIME SETUP"]
        S1[Create Company<br/>Haritha Hospitals]:::setup
        S2[Create Departments<br/>36 depts]:::setup
        S3[Create Designations<br/>51 desigs]:::setup
        S4[Create Shift Location<br/>Hyderabad, 200m radius]:::setup
        S5[Create Holiday List<br/>2026 holidays]:::setup

        S7[Create Employees<br/>210 records]:::setup
    end

    subgraph Schedule["DAILY SCHEDULING"]
        D1[HR creates Shift Assignment<br/>per Employee per day]:::op

    end

    S1 --> S2 --> S3 --> S4 --> S5 --> S6 --> S7
    S7 --> D1
    S2 --> D1
    S6 --> D1
    D1 --> D3
    D2 --> D1
    D1 --> A3
    A1 --> A2
    A2 --> A3

```

**Key paths:**
- **Setup (blue)** happens once at deployment. Order matters: Company → Dept → Designation → Shift Location → Holiday List → Shift Types → Employees.
- **Scheduling (green)** happens daily. HR assigns who works which shift on which day.
- **Attendance (orange)** happens automatically every minute via scheduler, with manual override for missed check-ins.
- **Payroll (violet)** happens monthly. End-to-end flow from attendance to bank file.

## 2. Daily ops cycle

The 24-hour heartbeat of shift management. What runs when, who does what.

```mermaid
flowchart LR
    classDef cron fill:#dbeafe,stroke:#3b82f6,stroke-width:2px,color:#000
    classDef user fill:#dcfce7,stroke:#22c55e,stroke-width:2px,color:#000
    classDef data fill:#fed7aa,stroke:#f97316,stroke-width:2px,color:#000
    classDef sys fill:#ede9fe,stroke:#8b5cf6,stroke-width:2px,color:#000

    subgraph Morning["MORNING 06:00 – 10:00"]
        M1[Morning shift employees arrive]:::user
        M2[Biometric punches IN<br/>Employee Checkin created]:::data
        M3[process_auto_attendance<br/>marks Previous-day Absent if no checkin]:::cron
    end

    subgraph Midday["MIDDAY 12:00 – 14:00"]
        MD1[Manager checks Roster<br/>for today's coverage]:::user
        MD2[Identifies gaps<br/>missed check-ins]:::user
    end

    subgraph Afternoon["AFTERNOON 14:00 – 18:00"]
        A1[Afternoon shift starts]:::user
        A2[Biometric punches IN for A-shift]:::data
        A3[Process leave requests<br/>approve / reject]:::user
    end

    subgraph Evening["EVENING 18:00 – 22:00"]
        E1[Morning shift OUT<br/>Last check-out of day]:::data
        E2[Shift Assignment for next day<br/>reviewed by HR]:::user
    end

    subgraph Night["NIGHT 22:00 – 06:00"]
        N1[Night shift employees on duty]:::user
        N2[Security rounds<br/>manual check-ins]:::user
        N3[Midnight: cron rolls date]:::cron
    end

    M1 --> M2 --> M3
    MD1 --> MD2
    M3 --> MD1
    MD2 --> A3
    A1 --> A2 --> A3
    A3 --> E1
    E1 --> E2
    E2 --> N1
    N1 --> N2 --> N3
    N3 -.-> M1
```

**Cadence:**
- **Per-minute:** `process_auto_attendance` cron (continuous)
- **Per-day:** Manager checks Roster, reviews leave, plans next-day assignments
- **Per-shift:** IN punches at shift start, OUT punches at shift end
- **Per-month:** Payroll Entry on the 1st of next month (HR-driven, not shown here)

## 3. Roster SPA architecture

What happens when an HR manager opens `/hr/roster` in their browser. Request flow through the stack.

```mermaid
sequenceDiagram
    actor User as HR Manager<br/>(browser)
    participant DNS as DuckDNS<br/>pberpprod.duckdns.org
    participant Proxy as nginx-proxy<br/>:443 TLS
    participant Front as erp-prod-frontend-1<br/>nginx :8080
    participant Back as erp-prod-backend-1<br/>gunicorn :8000
    participant SPA as HRMS Roster SPA<br/>Vue 3 + Tailwind
    participant WS as erp-prod-websocket-1<br/>Socket.IO :9000
    participant DB as erp-prod-db-1<br/>MariaDB :3306

    User->>DNS: GET /hr/roster
    DNS-->>User: 144.217.163.228
    User->>Proxy: HTTPS :443
    Proxy->>Proxy: TLS termination
    Proxy->>Front: HTTP :8080
    Front->>User: SPA bundle (HTML + JS + CSS)
    User->>User: Vue mounts MonthViewTable.vue

    Note over User,SPA: SPA boots, fetches config

    User->>Back: GET /api/method/hrms.hr.page.roster.roster.get_employees?department=Nursing-ICU
    Back->>DB: SELECT name, employee_name FROM tabEmployee WHERE department=...
    DB-->>Back: 18 rows
    Back-->>User: JSON {employees: [...]}
    User->>Back: GET /api/resource/Shift Assignment?filters=[[employee,in,...], [start_date,<=,2026-08-31], [end_date,>=,2026-08-01]]
    Back->>DB: SELECT ... FROM tabShift Assignment WHERE ...
    DB-->>Back: ~540 rows
    Back-->>User: JSON {data: [...]}
    User->>Back: GET /api/resource/Shift Type?fields=[name,color]
    Back->>DB: SELECT name, color FROM tabShift Type
    DB-->>Back: 25 rows
    Back-->>User: JSON {data: [...]}

    Note over User,SPA: SPA renders month grid<br/>Cells colored by Tailwind palette<br/>G=blue, M=green, A=orange, N=violet

    User->>Back: POST /api/method/hrms.hr.page.roster.roster.assign_shift<br/>{employee, shift_type, date}
    Back->>DB: INSERT INTO tabShift Assignment (...)
    Back-->>User: 200 OK
    Back-)WS: emit "shift_assigned" event
    WS-->>User: real-time push (other open browsers refresh)

    Note over User,DB: Each cell click = 1 API call + 1 DB write<br/>Bulk ops via Shift Assignment Tool (server-side)
```

**Tailwind color mapping at the SPA layer:**

```javascript
// apps/hrms/roster/src/components/MonthViewTable.vue (simplified)
const colors = {
  blue:    '#3b82f6',  // G — General
  green:   '#22c55e',  // M — Morning
  orange:  '#f97316',  // A — Afternoon
  violet:  '#8b5cf6',  // N — Night
}

// Each cell:
<td :style="{ backgroundColor: colors[shiftType.color] }">
  {{ shiftType.name }}  <!-- e.g., "M0600R0830" -->
</td>
```

**Critical:** color keys MUST be lowercase Tailwind names. If a Shift Type has `color='Blue'` (capitalized), the lookup `colors['Blue']` returns `undefined` and the SPA crashes with "Cannot read properties of undefined (reading '300')" (Lesson #157). The `Shift Type-color-options` Property Setter in our `haritha_hospital` fixtures prevents this by restricting the dropdown to lowercase values.

## 4. Auto Attendance data flow

The minute-by-minute cron job that turns biometric punches into Attendance rows.

```mermaid
sequenceDiagram
    participant Sched as bench-schedule<br/>cron: every minute
    participant Job as process_auto_attendance_for_all_shifts
    participant DB as MariaDB
    participant ShiftT as tabShift Type
    participant Emp as tabEmployee
    participant Checkin as tabEmployee Checkin
    participant Att as tabAttendance
    participant SA as tabShift Assignment

    Sched->>Job: trigger (every 60s)
    Job->>DB: SELECT name, last_sync_of_checkin FROM tabShift Type WHERE enable_auto_attendance=1
    DB-->>Job: 25 rows

    loop For each Shift Type
        Job->>Job: Check has_incorrect_shift_config()<br/>(must have last_sync_of_checkin)
        alt Config valid
            Job->>DB: SELECT * FROM tabShift Assignment<br/>WHERE shift_type=X AND status='Active'<br/>AND start_date <= NOW()<br/>AND (end_date IS NULL OR end_date >= NOW())
            DB-->>Job: N rows (active assignments)

            loop For each Assignment
                Job->>DB: SELECT * FROM tabEmployee Checkin<br/>WHERE employee=... AND time > last_sync_of_checkin
                DB-->>Job: M check-in rows

                alt Has check-ins
                    Job->>Job: Pair IN/OUT alternating
                    Job->>Job: Compute working_hours
                    Job->>DB: INSERT/UPDATE tabAttendance<br/>(status=Present/Half Day/On Leave/Holiday)
                else No check-ins AND date > process_attendance_after
                    Job->>DB: Check Holiday List for that date
                    alt Holiday
                        Job->>DB: INSERT Attendance status='Holiday'
                    else Not holiday
                        Job->>DB: Check Leave Application for that date
                        alt Approved leave
                            Job->>DB: INSERT Attendance status='On Leave'
                        else No leave
                            Job->>DB: INSERT Attendance status='Absent'
                        end
                    end
                end
            end

            Job->>DB: UPDATE tabShift Type SET last_sync_of_checkin=NOW() WHERE name=X
        else Config invalid (Lesson #42)
            Job->>Job: silently skip (no error)
        end
    end
```

**Why `last_sync_of_checkin` is critical:** if NULL, the function `has_incorrect_shift_config()` returns True and the shift is silently skipped. Symptom is "scheduler runs every minute but marks zero attendance". Always set this to a future timestamp on Shift Type creation (Lesson #42).

## 5. Data migration flow

When we promote code from dev to prod, or seed a new env with prod's master data.

```mermaid
flowchart TB
    classDef fetch fill:#dbeafe,stroke:#3b82f6,stroke-width:2px,color:#000
    classDef mig fill:#dcfce7,stroke:#22c55e,stroke-width:2px,color:#000
    classDef data fill:#fed7aa,stroke:#f97316,stroke-width:2px,color:#000

    subgraph Source["SOURCE ENV (prod)"]
        A1[frappe API<br/>/api/resource/<DocType>]:::fetch
        A2[fetch_master_data.py<br/>writes /tmp/prod_<DocType>.json]:::fetch
    end

    subgraph Transfer["TRANSFER"]
        B1[JSON files<br/>scp to target container]:::data
    end

    subgraph Target["TARGET ENV (dev)"]
        C1[migrate_master_data.py<br/>reads JSON, upserts via ORM]:::mig
        C2[DocType 1: Company<br/>2-step insert + accounts]:::mig
        C3[DocType 2-9: Account, Cost Center,<br/>Department, Designation, Item Group,<br/>UOM, Gender, Employment Type]:::mig
        C4[DocType 10: Shift Type<br/>autoname=prompt, set name explicit]:::mig
        C5[DocType 11: Shift Location]:::mig
        C6[DocType 12: Holiday List]:::mig
        C7[DocType 13: Employee<br/>remap by attendance_device_id]:::mig
        C8[DocType 14: Item]:::mig
        C9[DocType 15: Shift Request<br/>before SA, employee remap]:::mig
        C10[DocType 16: Shift Schedule<br/>drop repeat_on_days child, refetch]:::mig
        C11[DocType 17: Shift Assignment<br/>remap employee, nullify SSA link]:::mig
    end

    A1 --> A2
    A2 --> B1
    B1 --> C1
    C1 --> C2 --> C3 --> C4 --> C5 --> C6 --> C7 --> C8 --> C9 --> C10 --> C11
```

**Idempotency:** each step uses `frappe.db.exists()` → `.save()` or `.insert()` (Lesson #157 pattern). Re-running the script is safe.

**Gotchas (per Lesson #157):**
1. `get_doc()` needs `doctype` key
2. Company default accounts = 2-step (insert → set_value)
3. Account root nodes = skip
4. Shift Type autoname='prompt' = explicit name
5. Department root = skip
6. Employee missing lookup data = migrate lookup first
7. Employee ID remap = lookup by `attendance_device_id`
8. Child tables stripped = explicit fetch
9. HRMS validate_approver = Department Approver must exist
10. autoname='field.######' = Series pre-bump

See [`/scripts/migrate_master_data.py`](../../../scripts/migrate_master_data.py) for the full implementation.

## 6. Roster cell click → Shift Assignment flow

What happens when the manager drags / clicks a cell in the Roster SPA to assign a shift.

```mermaid
sequenceDiagram
    actor HR as HR Manager
    participant SPA as Roster SPA<br/>MonthViewTable.vue
    participant API as /api/method/<br/>hrms.hr.page.roster.roster
    participant DB as MariaDB
    participant Hooks as hooks.py<br/>doc_events

    HR->>SPA: click empty cell at (Nurse A, 2026-09-05)
    SPA->>SPA: open shift picker modal
    HR->>SPA: select "M0600R0830"
    HR->>SPA: click "Assign"
    SPA->>API: POST assign_shift(employee=HR-EMP-00001, shift_type=M0600R0830, date=2026-09-05)

    API->>DB: SELECT * FROM tabShift Assignment<br/>WHERE employee=... AND start_date=... AND end_date=...
    alt Existing assignment
        API->>DB: UPDATE tabShift Assignment SET shift_type=M0600R0830
        DB-->>API: 1 row updated
    else New assignment
        API->>DB: INSERT INTO tabShift Assignment (name, employee, shift_type, start_date, end_date, status='Active', docstatus=1)
        DB-->>API: 1 row inserted
    end

    API->>Hooks: doc_events on_update Shift Assignment
    Hooks->>DB: UPDATE related Shift Schedule Assignment if linked
    Hooks-->>API: ok

    API-->>SPA: 200 OK {success: true}
    SPA->>SPA: update local grid cell color
    SPA-->>HR: visual confirmation
```

**Note:** in HRMS standard, the Roster cell click triggers the `hrms.hr.page.roster.roster` API. For bulk operations (assigning a whole department a shift for a date range), use the **Shift Assignment Tool** (server-side) instead — it's much faster for >50 assignments.
