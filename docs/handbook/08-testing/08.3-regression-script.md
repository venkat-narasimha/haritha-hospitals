# 08.3 — Regression Test Script (8-Phase Playbook)

> **For:** Admin / Venkat running a full regression test on Haritha Hospitals ERPNext.
> **Goal:** Single source of truth for the 8-phase test playbook (LEARNINGS #48) — copy, run, report.

## Purpose

The 8-phase regression script is the **mandatory test flow** for any major change:

- New module / app install
- Schema migration
- Quarterly regression
- Pre-upgrade validation
- Post-incident verification

Total runtime: ~4 hours for full regression; ~1.5 hours for 8-phase lite.

> **Venkat's standing rule (LEARNINGS #48, set 2026-08-10):** After ANY new module/app/config is installed, ALWAYS proactively offer to run this 8-phase playbook. Non-negotiable.

---

## When to run

| Trigger | Plan | Time |
|---|---|---|
| `bench install-app <X>` | Full 8-phase | ~4 hours |
| Schema change (CF/PS/PF/LH on critical DocType) | Lite (Phases 1–6) | ~1.5 hours |
| Quarterly cadence | Full 8-phase + Phase 7 (60+ cases) | 1 day |
| Pre-upgrade (Frappe/ERPNext/HRMS major version) | Full 8-phase | ~4 hours |
| Post-incident verification | Affected phases only | ~30 min |
| Deploy to prod | Smoke (Phase 1) + targeted phases | ~15 min |

## Phase 1 — Smoke (~5 min)

**Goal:** System boots, UI loads, no 500 errors.

### Curl tests (HTTP 200)

```bash
# All 3 envs respond?
for env in dev qa prod; do
  case $env in
    dev)  url="https://pberpDEV.duckdns.org" ;;
    qa)   url="https://pberpqa.duckdns.org" ;;
    prod) url="https://pberpprod.duckdns.org" ;;
  esac
  echo -n "$env: "
  curl -sk -o /dev/null -w "%{http_code}\n" "$url"
done
# Expected: 200 200 200
```

### Login test

```bash
# Login as Administrator via API
curl -sk -c /tmp/cookies.txt \
  -X POST "https://pberpprod.duckdns.org/api/method/login" \
  -d "usr=administrator&pwd=$ADMIN_PASS"
# Expected: HTTP 200, JSON with home_page URL

# Verify session
curl -sk -b /tmp/cookies.txt \
  "https://pberpprod.duckdns.org/api/method/frappe.auth.get_logged_user"
# Expected: "administrator"
```

### List views load

```bash
# Hit key DocType list endpoints
for doctype in Employee Shift Type Attendance Leave Application Salary Slip; do
  echo -n "$doctype: "
  curl -sk -b /tmp/cookies.txt \
    "https://pberpprod.duckdns.org/api/resource/$doctype?fields=%5B%22name%22%5D&limit_page_length=1" \
    | jq -r '.data | length' \
    | head -1
done
# Expected: 1 (at least 1 record exists)
```

### Pass criteria for Phase 1

- [ ] All curl tests return 200
- [ ] Login succeeds
- [ ] All 5 DocType list endpoints respond
- [ ] No errors in browser console

> **If any smoke fails:** Stop. Investigate before proceeding.

**Goal:** All expected customizations present and correctly tagged.

### Verify haritha_hospital app installed

```python
frappe.db.get_value("Installed Applications", {"app_name": "haritha_hospital"}, "app_version")
# Expected: a version string like "0.0.1"
```

### Sanity: no orphan customizations

```python
# CF that reference missing DocType
orphan_cf = frappe.db.sql("""
    SELECT name, dt FROM `tabCustom Field`
    WHERE module = 'haritha_hospital'
      AND dt NOT IN (SELECT name FROM `tabDocType`)
""")
print(f"Orphan CFs: {len(orphan_cf)}")  # Expected: 0

# PS that reference missing DocType
orphan_ps = frappe.db.sql("""
    SELECT name, doc_type FROM `tabProperty Setter`
    WHERE module = 'haritha_hospital'
      AND doc_type NOT IN (SELECT name FROM `tabDocType`)
""")
print(f"Orphan PS: {len(orphan_ps)}")  # Expected: 0
```

### Pass criteria for Phase 3

- [ ] All counts match expected (78/189/3/2/2)
- [ ] haritha_hospital in Installed Applications
- [ ] 0 orphan customizations

> **If counts differ:** investigate missing customizations. Re-export fixtures if needed.

## Phase 6 — Integration (~30 min)

**Goal:** Cross-module flows work.

### Checkin → attendance → payroll (end-to-end)

```bash
bench --site pberpprod.duckdns.org console
```

```python
import frappe
from frappe.utils import today, add_days

emp = "Test Smoke"  # use the fixture employee
date = today()

# 1. Insert Employee Checkin
checkin = frappe.new_doc("Employee Checkin")
checkin.employee = emp
checkin.time = f"{date} 09:00:00"
checkin.log_type = "IN"
checkin.insert()
checkin.submit()

# 2. Force auto-attendance run
from hrms.hr.doctype.attendance.attendance import mark_attendance
# Or trigger the scheduled job:
frappe.flags.in_test = True
from frappe.utils.scheduler import enqueue_events
# Simpler: directly create Attendance
att = frappe.new_doc("Attendance")
att.employee = emp
att.attendance_date = date
att.status = "Present"
att.insert()
att.submit()
print(f"Attendance created: {att.name}")

# 3. Verify payroll sees it
ss_count = frappe.db.count("Salary Slip", {"employee": emp, "start_date": ["<=", date], "end_date": [">=", date]})
print(f"Related Salary Slips: {ss_count}")
```
