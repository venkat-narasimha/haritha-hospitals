## What is Haritha Hospitals ERPNext?

Haritha Hospitals ERPNext is a **complete hospital staff-management and payroll system** built on top of Frappe ERPNext + HRMS — running in production at a real 200+-employee hospital since 2026, with **every customization version-controlled in git** so your deployment is reproducible, auditable, and yours to own.

It is not a generic SaaS you rent. It is a **self-hosted, hospital-tuned, open-source core** with our 274 battle-tested customizations — covering shift scheduling, attendance, leave, payroll, and the Indian statutory stack (PF, ESI, TDS) — packaged into a custom app that can be installed on any Frappe environment with a single command.

## Key features

### HRMS — staff management

| Feature | What it does |
|---|---|
| **Shift Management** | 25 predefined shift types (Morning, Afternoon, Night, General) with monthly Roster grid, color-coded per shift, swap requests, automatic schedule templates |
| **Attendance** | Auto-marked from biometric check-ins every minute; manual override for missed punches; half-day / absent / leave / holiday detection |
| **Leave** | 7 leave types (Casual, Sick, Earned, etc.), per-employee annual allocation, approval workflow, leave balance carry-over, block lists for peak season |
| **Holidays** | Per-company holiday calendar linked to shifts + employees, automatic Holiday status on those dates |
| **Payroll** | Monthly Payroll Entry → Salary Slips → Journal Entry to GL → bank file; PF / ESI / TDS / professional tax out of the box |
| **Employee Checkins** | Raw biometric log; bi-directional sync with HRMS Roster |
| **Shift Request** | Employee-initiated shift swap requests, approver-driven, audit trail |
| **Recruitment** (future) | Job Opening → Applicant → Interview → Offer → Onboarding workflow |
| **Training** (future) | Training Program + Event + Result + Feedback |
| **Appraisal** (future) | Goal setting, KRAs, review cycles |

### Hospital-specific customizations

Built into our custom app (`haritha_hospital`), 78 Custom Fields and 189 Property Setters tuned for hospital workflows:

- **Employee** — Default Shift, Approvers (Leave / Expense / Shift), PAN, IFSC, MICR, Health Insurance, Payroll Cost Center, Provident Fund Account
- **Department** — Payroll Cost Center linkage for cost allocation
- **Company** — Default accounts for Payroll Payable, Employee Advance, Expense Claims, plus HRA / Basic / Arrear salary component references
- **Holiday handling** — Per-employee Holiday List, weekend rules, region-specific calendars
- **Shift Type** — Color coding aligned with the HRMS Roster SPA, on-call / emergency shift tags

### Custom App — portability

All 274 customizations ship as **JSON fixtures** inside the `haritha_hospital` Frappe app. Reproduce any environment from scratch with three commands:

```bash
bench get-app haritha_hospital git@github.com:venkat-narasimha/haritha_hospital.git
bench --site <yoursite> install-app haritha_hospital
bench --site <yoursite> migrate
```

Result: same customizations on dev, staging, prod, future replicas. No manual re-clicking through the UI.

## Why choose us

1. **Built specifically for hospital operations.** Not a generic HR system with hospital as an afterthought — every Custom Field, every Property Setter, every workflow reflects how a real 200+-employee hospital runs shifts, attendance, and payroll. We've been running this in production since 2026 with 8,000+ shift assignments and 6,300 attendance records.

2. **HRMS-first design (not bolted on).** Most ERPs treat HR as one module among many. Haritha puts HRMS at the center — Shift Management is the first screen your HR manager opens every morning, not a side menu. This is the system our users actually use, every day, all day.

3. **274 production-validated customizations.** Every Custom Field, Property Setter, Print Format, Notification, and Letter Head has been live in production, exercised by real users, and proven against the edge cases that break naive deployments (e.g., Tailwind color case-sensitivity in the Roster SPA, HRMS `last_sync_of_checkin` defaults, employee ID remapping across environments).

4. **Disaster-recovery tested.** We don't just claim backups — we've executed the recovery. Automated daily backups (3-2-1 rule: 3 copies, 2 media, 1 offsite), offsite push to a separate VPS, SHA256 verification, monthly heartbeat checks. RTO (recovery time objective) and RPO (recovery point objective) targets documented and tested.

5. **Full ownership of customization code.** Our 274 customizations live in a public GitHub repo under our organization's control. No vendor lock-in. No "we'll email you the patches". You can fork it, audit it, modify it, or hire any Frappe developer in the world to maintain it.

## What this means for your hospital

If you're evaluating this for your own hospital:

- **Time to value:** ~1 week to deploy + populate 200 employees + 25 shifts + holiday list. The migration script (`migrate_master_data.py`) replays our prod data into your env in minutes.
- **Customizations are not magic.** Every Custom Field and Property Setter is in the repo, named clearly, with a fixture export. Your team (or any Frappe developer) can read the code and understand what each one does.
- **No surprises.** If we vanish tomorrow, your hospital keeps running. The customizations are yours, the code is in your GitHub, the data is in your MariaDB.
- **Path forward.** Once you're live on shift + attendance + leave + payroll, additional modules (full accounting, inventory, pharmacy, lab, billing, patient management) can be added incrementally without disrupting what works.
