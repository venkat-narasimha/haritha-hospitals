## Pre-demo checklist

Run through this the morning of the demo, ideally 30–60 minutes before the call.

### Access

- [ ] **Admin login** — confirm `Administrator` / `admin123` works on pberpprod (or whichever env you'll demo). Test login from the same machine you'll use to share screen.
- [ ] **Test data** — verify there are records visible on the demo (210 employees, 25 shift types, 8,000+ shift assignments, 6,300 attendance). Run this query: `SELECT COUNT(*) FROM tabEmployee` (should be ≥210).
- [ ] **Roster page** — open `/hr/roster` in Chrome; confirm the month grid renders (no "Cannot read properties of undefined" — see [Lesson #157](#troubleshooting-tips)).
- [ ] **Browser** — use Chrome or Edge. Firefox sometimes has Tailwind class loading quirks; Safari on iPad works but stick with desktop Chrome for the demo.

### Screen share

- [ ] **Test screen share** — Zoom / Teams / Meet — test 10 min before the call starts.
- [ ] **Close distractions** — Slack, email, calendar notifications, IDE, terminal. The demo should be the only thing visible.
- [ ] **Tabs pre-loaded** — open these tabs in advance:

  5. `https://github.com/venkat-narasimha/haritha_hospital` (GitHub repo, to show the custom app)

### Materials

## Demo flow — step-by-step

### Step 1 — Login + landing dashboard (1 min)

**What to click:** open `https://pberpprod.duckdns.org/desk`, enter `Administrator` / `admin123`.

**What to say:**
> "This is the Haritha Hospitals ERPNext dashboard. Every user sees a customized workspace depending on their role — HR managers see HR shortcuts, accountants see finance shortcuts. Today I'll walk you through the HR manager's view."

**What to highlight:**
- Single sign-on across modules (no separate logins for payroll, attendance, etc.)
- Workspace cards give instant visual summary of what's pending
- Search bar at top can find any record by name (try `M0600R0830`)

---

### Step 2 — Show Company record + custom fields (2 min)

**What to click:** Search → "Company" → open "Haritha Hospitals".

**What to say:**
> "One Company record, but notice the tabs: HR & Payroll, Accounting, Manufacturing. The HR & Payroll tab is the magic — it links this company to its default payroll accounts. Without these links, payroll wouldn't know where to post salaries in the chart of accounts."

**What to highlight:**
- `default_payroll_payable_account` → links to "Salaries Payable" GL account
- `default_employee_advance_account` → "Employee Advances"
- `basic_component`, `hra_component`, `arrear_component` → Salary Components used by all salary structures

---

### Step 3 — Navigate to HRMS module (1 min)

**What to click:** Click the HR module icon (or search "HR").

**What to say:**
> "HRMS is the core of this deployment. Notice all the sub-modules: Employee, Attendance, Leave, Shift, Payroll, Recruitment, Training. We'll focus on Shift today, then loop back through Attendance and Payroll."

---

### Step 4 — Show Employee list, filter by Department (3 min)

**What to click:** Employee → List. Filter by Department = "Nursing - ICU".

**What to say:**
> "210 employees across 36 departments. Filter to ICU nursing — 18 people. Each row has department, designation, default shift, attendance device ID, status. The attendance device ID is what links to their biometric — it's the FK that connects this HR record to the physical check-in system."

**What to highlight:**
- The `attendance_device_id` is the bridge to biometric integration
- Custom fields (PAN, IFSC, bank, approvers) are visible on each row
- "Active" status is what allows attendance / payroll transactions; "Left" status freezes them

---

### Step 5 — Open Employee record, show custom fields (3 min)

**What to click:** Click on `HR-EMP-00001` (or any employee).

**What to say:**
> "Every employee has a master record. Standard HRMS fields plus our custom additions: default shift (auto-attendance fallback), three approvers (leave, expense, shift), payroll cost center, bank details, PAN, IFSC, PF account number. Notice the autoname — HR-EMP-00001 — Frappe assigns these automatically as you create records."

**What to highlight:**
- Custom Fields visible on the form (these are the 78 Custom Fields from our fixtures)
- Tab breaks (HR, Payroll, Bank) organize the form into logical sections
- Approvers are link fields — click to jump to the User record

---

### Step 6 — Navigate to Shift Type list, show colors + naming (2 min)

**What to click:** Search → "Shift Type". Open the list.

**What to say:**
> "25 shift types, each with a 10-character code: prefix + start time + regular/special + duration. G0900R0830 means General, 09:00 start, Regular end, 8.5 hours duration. The color is what shows in the Roster grid — note they're lowercase Tailwind names: blue, green, orange, violet."

**What to highlight:**
- The 10-char naming convention (mention the [02.1 doc](../02-workflow/02.1-shift-management-workflow.md#shift-type-naming-conventions) for full details)
- Color palette is restricted by a Property Setter (prevents typos)
- Open one record and show grace periods, late entry detection, etc.

---

### Step 7 — Open Roster `/hr/roster` — show month view with colored shifts (3 min)

**What to click:** Navigate to `https://pberpprod.duckdns.org/hr/roster`.

**What to say:**
> "This is the Roster. A month grid showing every employee's shift for every day. Each cell is colored by the shift type — green for Morning, orange for Afternoon, violet for Night. Hover any cell for the shift details. This view is rendered by an SPA built in Vue 3 + Tailwind, talking to the same Frappe backend."

**What to highlight:**
- Color = instant visual pattern recognition (a manager can spot coverage gaps at a glance)
- The SPA is the same Frappe API your team would build custom reports on
- Mention: this was built by Frappe's HRMS team; we just configured the data

---

### Step 8 — Filter Roster by Department, then by Employee (2 min)

**What to click:** Use the Department filter at the top, select "Nursing - ICU". Then click on a single employee row.

**What to say:**
> "Filter to one department — 18 employees, manageable view. Click any employee to drill down to their personal shift schedule. Notice how easy it is to spot who's on Night shift when, who's rotating to Afternoon, who's been on Morning all month."

---

### Step 9 — Show Attendance list, mark attendance (3 min)

**What to click:** Search → "Attendance" → List. Filter by today (or recent date).

**What to say:**
> "These rows were created automatically by the scheduler running every minute. It reads biometric check-ins, pairs IN/OUT, computes hours, and creates Attendance rows. Status comes from check-ins + leave applications + holiday list."

**Action to take:** Click "New" and manually mark attendance for one employee for today's date. Set status = Present. Submit.

**What to highlight:**
- Auto-marking is invisible until it doesn't work — when biometric fails, you mark manually
- Status options: Present / Absent / On Leave / Half Day / Holiday / Work From Home
- The shift field auto-populates from the employee's Shift Assignment for that date

---

### Step 10 — Show Holiday List (1 min)

**What to click:** Search → "Holiday List" → "Haritha Hospitals Holiday List".

**What to say:**
> "Org-level holiday calendar. Linked to each Shift Type and each Employee. When an employee is scheduled on a holiday, attendance auto-marks as 'Holiday' instead of 'Absent' — and they get paid for that day."

---

### Step 11 — Show Salary Slip / Payroll summary (3 min)

**What to click:** Search → "Salary Slip" → open one from the current month.

**What to say:**
> "One slip per employee per month. Earnings: Basic, HRA, Special Allowance, Arrears. Deductions: PF, ESI, TDS, Professional Tax. Net pay = Earnings − Deductions. Every component is a Salary Component that you can define; every formula can be customized in Python."

**Action to take:** Click "Salary Slip" → "Show Salary Structure" to show the parent structure.

**What to highlight:**
- The salary slip reads from the same Attendance data the manager sees in the Roster
- One click to generate slips for the whole company (Payroll Entry → Create Salary Slips)
- Submit posts a Journal Entry to the GL — accounting is integrated, not bolted on

---

### Step 12 — Show Reports — HR Analytics (2 min)

**What to click:** Reports → HR → "Monthly Attendance Sheet".

**What to say:**
> "HRMS ships with 30+ HR reports out of the box. This Monthly Attendance Sheet is the one HR uses most: present / absent / leave / holiday counts per employee per day. Export to Excel or PDF."

**What to highlight:**
- Reports are SQL-based (Query Reports) or Python-based (Script Reports)
- Custom reports are easy to add — we'll add any report your team needs

## What NOT to show

Known limitations and work-in-progress — avoid bringing these up unless the client specifically asks.

- **Recruitment / Training / Appraisal modules** — installed but not configured. Don't demo these; say "available, not yet activated".
- **Pharmacy / Lab / Patient management** — out of current scope. Don't promise these; refer to the [01.1 Schema Reference](../01-schema/01.1-schema-reference.md) for what's actually built.
- **Multi-company / Multi-currency** — Haritha runs single-company. If the prospect needs multi-company (e.g., hospital chain), say "Frappe supports it natively; we'd scope it for v2".
- **HRMS v16.5.1+ bug** — there's a known bug in upstream HRMS (`repost_allowed_types` phantom field). We're pinned to v16.5.0. Don't go deep unless asked.
- **Custom-built Roster SPA bug history** — there was a Tailwind color case-sensitivity crash in development; we fixed it via Property Setter. Mention only if asked about reliability.
- **Backup cron recovery story** — only show if asked about DR. We have it tested, but the 03.1 one-pager is enough for most prospects.

## Common Q&A

For deeper coverage of common questions, see [03.3 FAQ](03.3-faq.md). Quick answers for the most common:

- **Q: "How long until we're live?"** A: 1 week for a fresh install. 2-3 days for migration from another system with similar data.
- **Q: "What if our hospital has 500 employees instead of 210?"** A: Frappe scales linearly; tested up to 10,000 employees in the open-source community.
- **Q: "Can our team modify the code?"** A: Yes — any Frappe developer. The customizations are well-documented and follow Frappe conventions.
- **Q: "What about Aadhaar / biometric integration?"** A: HRMS Employee Checkin API accepts any check-in source. We can integrate with your existing biometric vendor.
- **Q: "Multi-language?"** A: Yes — Frappe supports multi-language UI. Currently shipping in English; Hindi translation is straightforward.

## Troubleshooting tips

Common demo-day fires:

| Issue | Fix |
|---|---|
| Login fails | Use `Administrator` / `admin123`. If still failing, use a different demo env. |
| Roster SPA crashes with "Cannot read properties of undefined" | One Shift Type has uppercase color. Run: `UPDATE tabShift Type SET color='blue' WHERE color='Blue'` (Lesson #157) |
| Slow page load | First-load compiles assets; wait 5-10 sec. Subsequent loads are fast. |
| Network drop mid-demo | Have offline screenshots of the Roster + Employee list as fallback. |
| Client asks about something we don't have | Honest: "That's a great question. Let me get back to you with details within 24 hours." |
